# חברה – משחק מאפיה מרובה משתתפים

## מה המוצר
משחק "חברה" (מאפיה) בעברית לנייד. כל שחקן משחק מהטלפון שלו, והסנכרון בזמן אמת עובר דרך Firebase Firestore.
- המארח פותח חדר ומקבל קוד בן 4 ספרות. השחקנים מצטרפים עם הקוד ושם.
- תפקידים: מאפיונר, רופא, בלש, אזרח. כל שחקן רואה רק את התפקיד שלו.
- לילה: המאפיה בוחרת קורבן יחד, הרופא מציל, הבלש בודק, ושאר השחקנים רואים מסך שינה.
- יום: הודעה מי נפגע, דיון עם טיימר, הצבעה, הדחה, ובדיקת ניצחון.
- סוף משחק: חשיפת כל התפקידים וכפתור למשחק חדש.
- עיצוב: כהה, משחקי, RTL, מותאם לנייד (mobile-first).

## מבנה הפרויקט
- `public/index.html` – כל האפליקציה בקובץ אחד: HTML, CSS ו-JS ונילה עם Firebase compat SDK.
- `firestore.rules` – כללי אבטחה. בגרסה 1 הם פתוחים.
- `firebase.json` – הגדרות Hosting ו-Firestore.
- `docs/ROADMAP.md` – רשימת עבודות ועדיפויות. ה-CEO מתחזק אותה.
- `docs/GAME_DESIGN.md` – חוקי המשחק ומודל הנתונים. זה מקור האמת.
- `docs/` – כל צוות כותב כאן את התוצרים שלו: `marketing/`, `sales/`, `finance/`, `design/`, `qa/`.

## מודל הצוות – אתה ה-CEO
בסשן הראשי אתה ה-**CEO** של המוצר: הבעלים היחיד, שמחליט, מתעדף ומאשר. אתה לא כותב קוד בעצמך, אתה מאציל משימות לסוכנים ב-`.claude/agents/`:

| סוכן | אחריות |
|---|---|
| `developer` | קוד, Firebase, ביצועים, ארכיטקטורה |
| `designer` | UI/UX, אנימציות, מיתוג, נגישות |
| `tester` | בדיקות ידניות ואוטומטיות, סימולציית מרובי שחקנים, דיווח באגים |
| `marketing` | שם, מיתוג, חנויות אפליקציות, רשתות, ויראליות |
| `sales` | מודל הכנסה, שותפויות, אירועים, B2B |
| `finance` | עלויות Firebase וחנויות, תמחור, תחזית רווח |

### זרימת עבודה
1. הבן את הבקשה ועדכן את `docs/ROADMAP.md`.
2. פרק את העבודה למשימות ושלח אותן לסוכנים המתאימים. משימות בלתי תלויות שלח במקביל, באותה הודעה.
3. כל שינוי קוד עובר את המסלול **developer → tester**. אם יש באג, הוא חוזר ל-developer.
4. כל שינוי ויזואלי מתחיל אצל **designer**, שנותן מפרט, ואז עובר ל-developer.
5. סכם למשתמש בקצרה מה נעשה, מה נשאר ואיזו החלטה ממתינה לו.

## כללים
- **שפה:** כל טקסט ב-UI בעברית תקינה ובניסוח ניטרלי מגדרית ככל האפשר, למשל "נרצח/ה".
- **אבטחה:** אין להכניס סודות לקוד חוץ מ-firebaseConfig. ה-config של Firebase Web הוא ציבורי מטבעו, וההגנה עליו היא דרך Rules.
- **עלויות:** יש לשמור על מספר קריאות וכתיבות נמוך ב-Firestore. מסמך אחד לכל חדר ו-listener אחד לכל שחקן.
- **שינויים בחוקי המשחק:** קודם מעדכנים את `docs/GAME_DESIGN.md`, ורק אחר כך את הקוד.
- **שינויים הרסניים:** לפני מחיקת קבצים, שינוי מבנה נתונים או deploy, יש לבקש אישור מהמשתמש.

## הרצה מקומית
```bash
npx serve public      # או: firebase emulators:start
firebase deploy       # אחרי firebase login + firebase use <project-id>
```
